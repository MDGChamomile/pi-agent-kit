# Pi Whitebox

[English](README.md)

Whitebox는 테스트, 빌드 및 프로젝트 스크립트를 엄격한 오프라인 Bubblewrap 경계 안에서 실행하는 Linux 전용 Pi 확장 기능입니다.

모델이 작업 방법을 스스로 선택하게 두면서, 프로젝트 명령 실행과 Pi 파일 도구에는 단단한 경계만 적용합니다.

## 보호 경계

Whitebox 모드에서는:

- `whitebox_run` 명령에 현재 Git 작업공간만 읽기·쓰기로 제공합니다.
- 루트 `.git` 디렉터리는 읽기 전용으로 마운트됩니다.
- 샌드박스 내 명령에는 네트워크, 상속된 환경변수, Pi 세션, 호스트 인증정보가 제공되지 않습니다. 작업공간과 아래에 명시한 읽기 전용 런타임 마운트에는 접근할 수 있지만, 그 밖의 호스트 홈 디렉터리에는 접근할 수 없습니다.
- Pi의 `read`, `write`, `edit`, `grep`, `find`, `ls` 도구는 작업공간 안으로 제한됩니다.
- 호스트 Bash와 사용자 `!`·`!!` 명령은 차단됩니다.
- 실행 시간, 출력 크기, 동시 실행을 제한합니다.
- 시작 검사, 신뢰 소스와 작업공간의 중첩 검사, 런타임 동일성 검사, 도구 소유권 확인이 실패하면 안전하게 차단합니다.

Whitebox가 격리하는 대상은 프로젝트 명령과 위 여섯 파일 도구입니다. Pi 프로세스 전체, 모델 통신, 명시적으로 추가한 다른 확장 기능, 쓰기 가능한 프로젝트 자체를 격리하는 것은 아닙니다.

중요한 미커밋 변경사항이나 비밀정보가 없는 일회용 프로젝트 사본에서 사용하세요. 강한 악성 코드나 자원 고갈 공격에는 별도 가상 컴퓨터를 사용해야 합니다.

## 요구사항

- Linux
- Node.js 22.19 이상
- Pi coding agent 0.84.2 또는 0.84.3(정확한 검증 버전 허용 목록이며, 그 밖의 버전은 시작을 차단함)
- `--disable-userns`를 지원하는 `/usr/bin/bwrap`(Bubblewrap 0.8.0 이상)과 `/usr/bin/flock`
- `/usr/bin` 아래의 `bash`, `python3`, `git`, ripgrep(`rg`)
- `/usr/bin/fd` 또는 Debian/Ubuntu의 `/usr/bin/fdfind`
- 네이티브 빌드에 선택적으로 필요한 `make`, `cc`, `c++`(Whitebox 시작에는 필요하지 않음)
- 실제 `.git` 디렉터리가 있는 일반 Git 저장소 루트 (worktree 미지원)
- 비특권 사용자 네임스페이스 활성화

현재 Node.js 22.22.3, Pi 0.84.2·0.84.3, Bubblewrap 0.9.0, Linux 6.8에서 테스트했습니다.

## 체크아웃에서 설치

```bash
git clone https://github.com/MDGChamomile/pi-agent-kit.git
cd pi-agent-kit/live/extensions/whitebox
npm install
npm link
```

이 명령은 `piw` 실행기를 설치합니다. Pi는 현재 Node 배포판과 함께 설치되어 있거나 `PATH`에서 실행 가능해야 합니다. 실행기는 선택한 Pi 패키지 또는 Whitebox 확장 소스가 작업공간과 중첩되면 시작을 거부합니다. 링크한 Whitebox 체크아웃은 검사할 프로젝트 밖에 두세요. 이 저장소 자체를 검사하려면 별도로 설치한 사본을 사용해야 합니다.

## 실행

검사할 일회용 프로젝트의 루트에서 실행합니다.

```bash
cd /path/to/project
piw
```

`piw` 실행기는 의도적으로 Whitebox 확장 기능만 로드한 상태로 Pi를 시작합니다.

```text
pi --no-extensions -e <whitebox>/index.ts --no-skills --no-approve --whitebox
```

추가 인자는 Pi로 전달됩니다. 다른 확장 기능을 명시적으로 불러오면 그 확장 기능은 호스트 권한으로 실행되므로 신뢰 경계가 넓어지며, 준비 상태에는 경계 밖에 남은 활성 호스트 도구 수가 표시됩니다. 실행기는 `package.json`에서 실행 파일을 소유한 패키지를 찾고 `bin.pi` 대상이 선택된 실행 파일과 일치하는지 확인합니다. 또한 샌드박스 worker가 동일한 canonical 패키지를 사용하도록 고정하고 위에 적은 Pi 버전만 허용합니다. `peerDependencies`의 와일드카드는 Pi 패키지 계약을 따르며, 실제 런타임 호환성은 허용 목록으로 제한합니다.

## 적합한 작업

- 테스트, 빌드, 린트, 프로젝트 스크립트
- 프로젝트에 이미 준비된 Node.js·Python 도구
- `git status`, `git diff`, `git log` 같은 읽기 전용 Git 확인

지원하지 않는 작업:

- 네트워크 접근 및 패키지 다운로드
- 호스트 인증정보가 필요한 명령
- 대화형 프로그램
- commit, merge, rebase, fetch, pull, push 같은 Git 변경

명령 실행의 기본 타임아웃은 120초이며, 최대 900초까지 설정할 수 있습니다. 명령 결과는 마지막 12KiB 또는 400줄만 본문으로 반환하고, 더 큰 출력은 필요할 때 `read`나 `grep`으로 확인할 캡처에 저장합니다. 진행 표시는 최신 4KiB만 유지합니다. 파일 도구 호출에는 작업공간 검사 중 협력적 취소를 포함해 부모 프로세스가 강제하는 120초 제한이 있습니다. 캡처 출력은 10MiB로 제한되며, 새 캡처는 이전 캡처 파일과 읽기 권한 레코드를 함께 대체합니다.

## 보안 유의사항

- 작업공간은 쓰기 가능하므로 내부 파일이 손상되거나 삭제될 수 있습니다.
- 작업공간의 모든 내용은 샌드박스 내 명령과 Pi 파일 도구가 읽을 수 있으며 모델 연결을 통해 전송될 수 있습니다. Whitebox는 프로젝트 내용의 기밀성을 보장하지 않습니다.
- 프로젝트의 `AGENTS.md` 같은 컨텍스트 파일은 Pi가 계속 읽을 수 있으며 모델 동작에 영향을 줄 수 있습니다. `--no-context-files`는 사용자의 전역 컨텍스트 지침도 함께 비활성화하므로, 이 동작을 인지한 경우에만 추가하세요.
- 지원 도구 실행을 위해 `/usr`의 읽기 전용 호스트 파일, `/etc`의 일부 신원·런타임 파일, `/opt/node`의 선별된 Node/npm/Pi 런타임이 보입니다. 그 밖의 전역 Node 패키지는 마운트하지 않습니다. 내부 런타임에는 `PI_OFFLINE=1`을 설정하며, Pi가 내려받지 않도록 `rg`와 `fd`가 미리 설치되어 있어야 합니다.
- 캡처 파일에는 정확한 원시 바이트를 보존합니다. Whitebox 파일 도구로 캡처를 읽거나 검색하면 Pi와 모델에 반환하는 텍스트에서 제어문자와 양방향 표시문자를 정리합니다. 일반 작업공간 파일 결과에는 Pi의 기존 동작을 유지합니다.
- CPU, 메모리, 작업공간 디스크 고갈을 완전히 통제하지 않습니다.
- Whitebox는 위험을 줄이지만 독립적으로 격리된 호스트를 대체하지 않습니다.

위협 모델과 취약점 제보 방법은 [SECURITY.md](SECURITY.md)를 참고하세요.

## 테스트

```bash
npm test
```

전체 테스트는 임시 Git 작업공간을 만들고 파일시스템, 네트워크, 환경변수, 네임스페이스, 실행 수명, 파일 도구, 실제 Pi 진입점 경계를 확인합니다. 외부 프로젝트 코드는 실행하지 않습니다.

GitHub 호스팅 러너(GitHub-hosted runner)는 Whitebox에 필요한 네트워크 네임스페이스 작업을 허용하지 않습니다. 따라서 CI에서는 호스팅 환경에서도 실행 가능한 정책 및 확장 연결 테스트를 `npm run test:portable`로 실행하며, 지원되는 Linux 호스트에서는 `npm test` 전체 통합 검사를 수행해야 합니다.
