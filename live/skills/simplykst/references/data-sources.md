# DART 우선 데이터 수집

## 순서와 최소 수집 범위

1. DART https://dart.fss.or.kr/ 에서 회사명·종목코드로 법인을 확정. 동명 회사, 자회사와 지주사 구분.
2. 최신 사업보고서와 이후 분기/반기보고서를 찾고 원보고서·정정/첨부정정·철회 여부를 확인. 기본 3년 재무 수치는 최신 보고서의 비교기간으로도 확보할 수 있으나 재작성/회계기준 변경을 기록.
3. 사업의 내용·재무제표·주석·감사의견·주식 총수/잠재증권·배당·최대주주/이사회·이해관계자 거래를 필요한 범위에서 읽음. 주석은 차입만기·담보/보증·약정·관련자 거래·자본증권·주식보상·후속사건을 우선. 금융은 자본적정성·자산건전성·유동성 경영지표도 수집.
4. 보고서 이후부터 분석일까지 유증, CB/BW, 소각·취득/처분 결과, 보호예수, 합병·분할·소송·제재 등 중요 변경을 조회. 자사주 계획과 실제 취득/소각 완료는 결과 공시·변경 주식 수 등으로 구분.
5. 정기보고서보다 최근 잠정 실적이 있으면 공정공시와 회사 실적자료로 보완하고 잠정임을 표시. 해당 실적이 반영된 정기보고서가 나왔다면 그것을 우선.
6. DART에 없는 시세·수급·시장조치·보호예수/상장 일정은 KRX/KIND, 필요시 KSD 등 해당 원천으로 이동. 사업 보충 자료는 기업 IR·금융회사 경영공시, 이후 검증 가능한 데이터 제공자·산업 원자료 순서. 시장 데이터나 애널리스트 컨센서스를 DART에서 제공한다고 가정하지 않음.

DART 문서 URL: `https://dart.fss.or.kr/dsaf001/main.do?rcpNo=<14자리 접수번호>`.
조회한 보고서명·공시일·접수번호·섹션/주석 번호를 원장에 남깁니다. 검색결과 요약만으로 재무 수치나 위험 부재를 확정하지 않습니다.

## 막혔을 때의 대체 절차

로컬 추출이 필요한 경우 다음을 확인합니다.

- 사용할 파서·도구가 설치되어 있는지 확인하고, 없으면 사용 가능한 도구나 아래 대체 경로를 선택합니다. 의존성을 승인 없이 설치하지 않습니다.
- 응답이 오류·접근 제한 페이지가 아닌 실제 문서인지 확인하고, 응답의 문자 인코딩에 맞게 해석한 뒤 한글·표가 정상적으로 읽히는지 확인합니다.
- 추출 성공과 실제 출력 파일의 경로·존재·비어 있지 않음을 확인한 뒤 읽습니다. 실패한 명령의 예상 출력 경로로 읽기를 반복하지 않습니다.

- 웹 원문 추출 실패 → DART 공개 뷰어/첨부 HTML·PDF·XBRL을 시도. 페이지 상호작용이 필요하면 브라우저 도구를 먼저 활성화. 목차 클릭 성공만으로 주석 열람을 인정하지 않고 iframe 본문 제목·기간·표가 실제로 바뀌었는지 다시 확인. PDF는 기존 설치 도구로 임시 경로에서 추출하고 표의 단위·기간 정렬 확인.
- DART 접근 제한 → 동일 공시를 제공하는 KIND 또는 기업 공식 첨부를 사용하고 `DART 원문 직접 확인 실패, 동일 공시 대체`로 표시. 접근 제한 우회 금지.
- 계정명 차이 → 계정 ID·주석·영문명·금융/비금융 재무제표 유형을 확인. API 미응답 또는 특정 계정 미존재를 0원으로 처리하지 않음.
- 컨센서스 부족 → 실제 공시 추세+사업 선행지표로 평가. 회사 목표·단일 증권사 추정·분석자 가정을 분리. 낡은 컨센서스를 최신 실적과 혼용하지 않음.
- 비교기업 부족 → 자기 과거/1~2개 직접 비교기업 또는 사업 시나리오. 선택 편향·경기고점·사업구조 변화를 점검. 경제적 비교 불가능이면 결측.
- 핵심 원자료와 허용 대체 모두 확보 못하면 어떤 자료가 왜 점수를 막는지 설명하고 사용자에게 해당 보고서 또는 API 접근이 필요하다고 알림. 반복 검색으로 주변 기사만 늘리지 않음.

자료 대체는 결측을 숨기기 위한 것이 아니라 경제적 질문을 유지하기 위한 것입니다. 원자료의 정의가 목적과 맞으면 사용하고 직접 재계산 미완료만으로 팩터 전체를 비우지 않습니다.

## OpenDART API가 필요한 경우

공개 DART 뷰어 열람에는 API 키가 필요하지 않습니다. 다수 연도·다수 종목을 반복 수집하거나 공시 목록·재무계정의 구조화 자동화가 필요하면 OpenDART API 사용을 권장합니다. API도 공시 주석의 해석이나 시장 데이터를 대신하지 않습니다.

이번 스킬은 **키 없는 공개문서 조사부터 실행**하며, API 연동 코드는 포함하지 않습니다. API가 필요해지면 수집 목적·대상·조회 범위를 사용자에게 설명하고 안전한 키 설정 및 연동을 별도로 진행합니다. 키가 없다는 이유로 전체 보고서를 즉시 중단하지 않습니다.

공식 출처:
- OpenDART: https://opendart.fss.or.kr/
- 공시검색 개발가이드: https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019001
- 재무정보 공개 조회: https://opendart.fss.or.kr/disclosureinfo/fnltt/singlacnt/main.do

공시검색 가이드 확인 사항:
- `GET https://opendart.fss.or.kr/api/list.json`, 필수 `crtfc_key`(40자리).
- `corp_code`는 8자리 법인 고유번호, 주식의 6자리 종목코드와 다름. 공식 고유번호 자료로 매핑.
- `bgn_de`, `end_de`, `page_no`, `page_count`를 사용. 페이지당 최대 100, 전체 페이지 처리. 법인 미지정 시 검색기간 제한 확인.
- `last_reprt_at=N`은 정정 포함 전체 보고서 검색. 최신 결과만 보지 말고 정정과 철회를 연결. 과거 분석은 접수일 cutoff 적용.
- 공시접수번호 `rcept_no`로 원문 연결. 목록 조회 성공을 본문 검토 완료로 해석하지 않음.
- `status=013` 자료 없음과 `020` 요청 제한, 인증 오류를 구분. 오류를 빈 재무값으로 변환하지 않음. 한도는 계정별로 달라질 수 있으며 무한 재시도 금지.
- 재무 API 사용 전 해당 최신 공식 가이드에서 보고서 코드·연결/별도 선택·단위·기간을 검증. 전체 재무제표 API가 주석 전문을 제공한다고 가정하지 않음.

## 키 보안

키는 채팅·보고서·검색 질의·저장소·명령행 인수·일반 웹 도구 URL에 넣지 않습니다. API 연동 시 사용자가 안전한 로컬 환경/비밀 저장소에 설정하도록 안내하고, 로컬 클라이언트가 런타임에 읽어 공식 OpenDART 호스트에만 전송하게 합니다. 키가 포함된 URL·HTTP 로그·예외 traceback은 출력하지 않습니다. 존재 여부만 확인하고 값을 조회·표시하지 않습니다. 비밀 설정이나 의존성 설치는 별도 승인 없이 변경하지 않습니다.

## 최신성·회계 일관성

- 시세/수급: 가격일과 거래소/세션, 데이터 제공시각 표기. 오래된 자료라면 현재 Trading 추천도를 만들지 말고 과거 기준 평가임을 명시.
- 재무: 분석일에 공개된 최신 정기보고서+그 이후 잠정실적/주요 사건. 감사보고서와 분기 검토보고서를 혼동하지 않음.
- 컨센서스: 제공자·기준일·기관 수(확인 가능하면)·추정기간을 표시. 최신 실적 발표 전 또는 90일 초과 자료는 현재 성장의 핵심 근거에서 제외. 단일 추정은 컨센서스가 아님.
- 주가·주식 수·배당권·희석은 같은 기준일로 조정. 서로 다른 정의의 BPS/ROE/순이익을 혼용하지 않음.
- 과거 자료가 재작성되면 최신 비교수치 사용, 원공시 수치와 차이를 설명. 과거 시점 검증에서는 당시에 알 수 없던 재작성을 소급 사용하지 않음.
